Roadmap, contributing and support

Unreviewed translation

This page was translated from the Portuguese (Brazil) original and has not yet been reviewed by a native or professional English speaker. If anything reads awkwardly, treat the Portuguese version as the source of truth.

Roadmap

The full public roadmap lives in GluView-comunidade/ROADMAP.md, in Now / Next / Later format (no promised dates — see why there). Here, the general development order already completed or in progress:

  1. Backend security foundation and audit.
  2. Data contracts, migrations and real time.
  3. Authentication, authorization and accounts.
  4. Web portal foundation (design system, internationalization).
  5. Patient dashboard.
  6. Caregiver dashboard.
  7. Alerts and reports.
  8. Documentation in three languages.
  9. Public API with integrator authentication.
  10. Public roadmap, issues and community process (this stage).
  11. Infrastructure, CI/CD and permanent hosting.
  12. QA, security and beta period.
  13. Release and ongoing operation.

How to contribute

The source-code repositories (GluView, GluSync, GluWebView) remain private for now — it isn’t possible to open a pull request directly against the code yet. That doesn’t prevent participating: see GluView-comunidade/CONTRIBUTING.md for what’s possible today (reporting a bug, suggesting a feature, fixing a translation/doc issue) and how it works in practice.

Support channels

  • Usage questions, suggestions: open a Discussion.
  • Bug, feature request, or translation/documentation issue: open an Issue — dedicated forms per type, with a privacy notice on each.
  • Security vulnerability or privacy incident (exposed data, unauthorized access, authentication failure): never open a public issue. Use GitHub Private Vulnerability Reporting on the community repository, or write to glusync.gluview@gmail.com — both channels carry the same commitment to confirm within 5 business days. The goal is to allow time to fix it before it becomes public. Describe the problem without including a token, password or another person’s data in the message.

See also troubleshooting before opening a ticket, and how to collect evidence without exposing sensitive data.
